# HERMES3D Studio + District Bot Mode

## Purpose
The public AGENTROPOLIS Agent MCP surface is presented as a cinematic virtual movie studio/backlot while preserving the existing governed runtime boundary.

## HERMES3D integration boundary
`iamlukethedev/Hermes3D` is an upstream visual/runtime reference, not a copied dependency in this change. Production integration must be adapter-based and license/provenance reviewed before vendoring assets or code.

The studio shell reserves the HERMES3D viewport role for:
- virtual backlot navigation
- camera/blocking visualization
- agent presence and production-state visualization
- execution/receipt state projection

It must not become an authority layer.

## District Bot Mode
Bot Mode is a district-scoped crew orchestrator under shared AGENTROPOLIS Layer-1 identity, mandate, policy, execution corridor, and audit controls.

Initial studio crew profiles:
1. Director — scene intent and orchestration
2. Producer — schedule, mandate and budget class
3. Camera — HERMES3D viewport and virtual camera planning
4. VFX — approved generative-media routing and provenance
5. 54-T Safety — effective capability/provider/runtime/egress verification
6. Auditor — receipts, provenance and rollback evidence

## Authority rule
UI arming is presentation/session state only. It does not grant runtime authority. Bot Mode cannot self-promote execution state, bypass authorization receipts, enable providers, or move DRY_RUN to CANARY/LIVE.

## Promotion sequence
`STANDBY -> PLAN -> AUTHORIZATION -> DRY_RUN -> CANARY_ELIGIBLE -> CANARY -> LIVE`

Each transition beyond planning requires its governing policy gate and receipt. CANARY and LIVE remain disabled until separately implemented and promoted.

## Visual direction
The public shell uses an original studio-lot treatment: soundstage, LED-volume screen, cameras, production lights, marquee, backlot rail, and governed crew console. It should evoke a premium film-production campus without copying a specific studio trademark, logo, or trade dress.
